## Prediction

The change should improve requirement fidelity, cross-system traceability, behavioral regression detection, review signal-to-noise, deterministic enforcement coverage, and safe incident-to-eval learning without increasing production autonomy.

## Changed behavior

- One authoritative system is declared per artifact while the repository remains the durable execution and audit record.
- Material or ambiguous work captures intent before specification; narrow, already-complete R0/R1 requests may skip the extra artifact.
- Semantic governance changes require representative real-agent behavior evidence, deterministic contract replay, and an independent semantic review bound to raw-response digests.
- Mandatory policies must map to deterministic enforcement evidence.
- Control bands start disabled and cannot authorize automatic production action by statistical threshold alone.

## Security and compatibility

- The behavior runner invokes only an explicit executable without a shell, uses a temporary working directory, passes a minimal environment unless variables are allowlisted, limits output, heuristically scans secrets, and refuses to overwrite existing response evidence.
- The runner is a trusted adapter launcher, not an OS sandbox. The adapter retains host filesystem, network, process, and credential permissions unless an external sandbox removes them.
- Raw live outputs are required for audit; heuristic scans do not replace human secret review and redaction before publication.
- Existing issue trackers remain compatible through stable IDs, immutable snapshots/digests/version-pinned references, and commit-SHA backlinks only when the external write is separately authorized.
- Existing projects are not mutated automatically; new templates are copied only through the already-authorized bootstrap workflow.
