Use the full change since the last appropriate validated baseline; quick success must not advance the integration baseline. ### Limits and operating decision

The optional workflow is locally usable, with conservative default fallback. Project owners must connect actual commands, maintain/review dependencies and input contracts, and compare occasional full regression with selection. The helper cannot prove undeclared dependencies or that an inner command disables its own affected-only/native cache behavior; release commands must satisfy the project's full/fresh policy themselves. POSIX macOS/Linux and canonical paths are required. Live-service, flaky or uncontrolled-environment checks stay uncached. Broad real impact still warrants broad regression.

Fresh/release/escalated execution removes old same-key successes and does not populate this helper's cache; a following local run may be cold. This intentional conservative behavior explained an observed five-check miss after release and is retained without a fabricated hit-rate claim. A cache hit also still incurs hashing/startup overhead; measure total waiting, queue time, failures/rework and missed regressions before claiming efficiency gains.

The full lifecycle, risk/security rules, independent release review, production/migration controls and protected CI/hosted trust gate remain. Risk/security/CI control files are unchanged from v5. Local user-authorized installation does not establish hosted promotion, signed reviewer identity, SHIP or a commercial application's acceptance. No business application files, external services or production systems were modified. Practice sources and scores are retained as candidates; no background learning or scheduler was added.
