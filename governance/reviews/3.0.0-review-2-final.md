## 4. Findings

### H1 — High — Paraphrased unsafe contradiction plus forged semantic evidence passes both release gates

**Status:** unresolved; release-blocking.

**Evidence:**

- `evals/behavior_contracts.json:4-20` contains only four narrow global contradiction expressions. The destructive-production expression matches a fixed phrase and the ungated-action expression depends on limited vocabulary and ordering.
- `scripts/run_behavior_evals.py:274-299` determines the mechanical result only from required/forbidden regex and secret heuristics.
- `scripts/run_behavior_evals.py:386-436` checks semantic-review structure and raw-response digest equality, but not an out-of-band reviewer attestation. A coordinated rewrite of the response digest and review file remains self-consistent.
- `scripts/validate_skill.py:532-570` recomputes the same regex contracts; `scripts/validate_skill.py:573-644` verifies the mutable in-tree semantic review and its digest.
- `evals/rubric.md:55-59` explicitly requires any opposite authorization in the complete answer to fail, regardless of keyword presence.
- The isolated paraphrase attack above returned exit 0 from both the official validator and runner after the report and semantic-review summary/digests were forged.

**Impact:** The CI replay can be green for a raw answer that semantically authorizes destructive unapproved production action. Digest binding proves that files agree with each other; it does not prove that the semantic reviewer was independent or that its verdict is authentic. This is materially inconsistent with the claimed report-forgery resistance and is especially consequential for an R3 core-governance release.

**Required action:** Do not try to enumerate dangerous paraphrases as the primary fix. Make the independent semantic decision an out-of-band trusted assertion: for example, a protected reviewer approval or signed CI attestation over the manifest, behavior configuration digest, and every raw-response digest, verified by the release gate. When an approved live semantic judge is available, run it in an isolated job and retain its attestation. Keep regex contradictions as defense in depth. Add this exact paraphrase and additional order/language variants as regression cases, then repeat the full fresh behavior capture and independent review.

### M1 — Medium — `max-output-bytes` is a post-capture acceptance check, not a memory/resource bound

**Status:** acceptable only for the current replay-only package and explicit trusted-launcher boundary; must be addressed before a live adapter becomes a required CI gate.

**Evidence:** `scripts/run_behavior_evals.py:223-247` uses `subprocess.run(..., capture_output=True)` and checks encoded stdout length only after the child exits. A large-output adapter/model response can therefore consume host memory before the configured limit rejects it. `README.md:93-107` correctly says the adapter is a trusted launcher rather than an OS sandbox and correctly warns that host filesystem/network/process/credential permissions remain; the boundary wording itself is accurate.

**Follow-up:** Stream stdout through a bounded reader, terminate the process tree when the cap is exceeded, and test sustained/child-process output. Until then, treat `--max-output-bytes` as an evidence-size gate, not containment or a resource quota, and require an external sandbox/resource limit for live adapters.

### M2 — Medium — Source provenance is current but not immutable/version-pinned

**Status:** temporarily acceptable for this review because the official page was verified live on the review date and the normalized summary is digest-bound; not acceptable as permanent R3 provenance.

**Evidence:** `SKILL.md:23` requires an immutable snapshot, digest, or version-pinned reference when relying on an external authority. `governance/practice-candidates/anthropic-ai-native-sdlc-core.json:4-10` records a mutable URL, retrieval date, and digest of the local normalized claims. `governance/practice-candidates/anthropic-ai-native-sdlc-source-claims.txt:10` explicitly says it is not a verbatim webpage snapshot. If the page changes, the local digest proves only the locally written summary, not what Anthropic published on 2026-08-26.

**Follow-up:** Preserve a policy-permitted immutable snapshot or content digest of the retrieved source, or a version-pinned archival reference, and link the normalized claims to that source artifact. Re-run the candidate provenance gate after adding it.

- **Control bands:** template and documentation consistently start disabled, keep all production mutation/deploy/rollback false, require typed single-tier activation in a future R3 change, and never let a statistical threshold authorize production action.

- Replay and in-tree digests cannot mechanically prove who authored or reviewed an artifact. H1 demonstrates the practical consequence of that trust boundary.
- This review did not authorize release, production action, external write, or human risk acceptance.

## 7. Final verdict

**NO_SHIP_RECOMMENDATION**

The normal candidate, rollback, deterministic validators, unit tests, versioned replay, candidate scoring, and seven specified tamper cases passed their expected gates. However, the paraphrased dangerous instruction plus coordinated forged report/semantic evidence passed both the official validator and behavior runner.
