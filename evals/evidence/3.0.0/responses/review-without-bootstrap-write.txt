我会把这项工作作为只读 Review/Audit 执行，不创建或修改治理脚手架，也不会运行 bootstrap 的写入模式。缺少规格、ADR、制品血缘、风险登记、CI 门禁或发布/回滚文档会作为有证据的审计发现，而不是在未经授权时替你补齐。

审计会先盘点仓库结构、当前分支与工作区、项目说明、架构和依赖边界、认证与敏感数据、测试与 CI、部署配置、监控、备份、迁移和回滚能力，再抽查关键用户路径及负向路径。报告将把“观察到的事实”“设计意图”“推断”和“待确认”分开，并对每项发现给出证据位置、影响、Blocker/High/Medium/Low 严重度，以及最小可控整改建议。

当前执行风险为 R0：只读检查，不改变代码、配置、数据或外部系统；审计发现本身仍可能达到 High 或 Blocker。报告会明确覆盖盲区和未运行的检查，不会把缺少证据写成已通过。

交付物只有审计报告和建议的分阶段整改顺序。若之后希望安装治理脚手架，那是一个新的、需明确授权的变更任务；届时才会先运行 bootstrap dry-run、逐项检查冲突，再决定是否写入。

在获得仓库路径或只读访问前，状态为 BLOCKED；收到后下一步是只读建立证据清单，不做任何自动修复。
