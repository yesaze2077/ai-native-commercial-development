Figma and specialist design tools are unavailable; that limits the design format, not all useful preparation. Reuse accepted requirements and available brand/component assets. If material requirements are still undecided, continue read-only analysis and the confirmation draft while their dependent design waits.

For an authorized design stage, keep a versioned local journey/state map, wireframes and a small HTML prototype using synthetic data. Specify the core path, empty/loading/validation/permission/error recovery, representative content, responsive layout and essential visual/focus tokens. Keep the prototype’s disposable, frontend-only or mocked boundaries explicit.

When local browser tools are available, exercise the prototype and later implementation, compare rendered views and record actual observations tied to the version. If they are unavailable, deliver the files and acceptance checklist with rendered/interaction validation marked unrun and assigned to the next available check. Do not invent a Figma file, browser result, accessibility certification or user study, and do not install tools or publish merely to fill the gap. An approved prototype is still not production integration or release evidence.
