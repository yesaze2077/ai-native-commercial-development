纯文案变更之后，原类型检查可能仍适用；运行时、锁文件和共享 API 契约改变之后，受影响的旧结果必须失效并重新验证。

| 变化 | 旧证据如何处理 | 下一步 |
|---|---|---|
| 只有 copy 文件变化 | 若确为非功能文案，且未影响类型生成、相关源码或传递依赖、输入、配置、环境和工具，原类型检查可复用 | 关联原运行记录并说明适用理由；检查文案差异及适用的页面显示，无需把原类型检查冒充新运行 |
| 运行时变化 | 依赖旧运行时的执行、构建和兼容性结论失效 | 在最终运行时下重跑相关检查 |
| 锁文件变化 | 受改变依赖及其传递依赖影响的类型、构建和行为结果失效 | 按最终锁定依赖安装，重跑受影响检查及适用的依赖安全检查 |
| 共享 API 契约变化 | 提供方、消费者和关键交互路径的旧契约/行为结果失效 | 验证契约、类型和相关集成/端到端路径，不能只测修改契约的一侧 |

整合后还要针对组合状态运行完整的受影响验证，包括相关类型检查、构建、单元/集成回归和 API 契约检查。各分支分别通过不能证明组合正确。项目要求的 CI 或受保护检查仍须在确切最终修订上执行。

没有被这些变化触及、且满足全部复用条件的证据可以保留；无法确认依赖或环境是否相关时，重跑相应检查。适用检查通过且没有新变化、失败或未解疑点后，停止重复验证。

报告时分别注明“原运行通过并复用”“因具体变化失效”“本次重新运行及结果”“尚未执行”。每项关联命令、原或新版本、相关配置/环境和证据位置；引用旧结果时保留其原时间与版本。这样能节省确实无关的重复工作，同时让结果可追溯。

本场景无工具和实际运行记录，以上仅判断证据适用性；尚未确认哪些具体结果可复用，也没有重跑或新增通过结果。
