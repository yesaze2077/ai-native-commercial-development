这是 R1 的本地功能变更，现有已接受 issue 已足以作为规范。直接围绕它实施，补充缺项即可，无需另建一份重复 PRD 或为窄改动生成完整 ExecPlan。

开始时读取适用的仓库说明，检查当前分支和未提交修改，并定位过滤入口、直接调用方及相关测试。保留已有改动，在符合项目要求的独立功能分支工作；单一写入者且工作区合适时不额外建 worktree，存在其他活动任务或隔离需要时再使用 worktree。

编码前引用 issue 的输入输出规则、空状态、验收和验证命令，形成此次最小改动范围。通过最窄的相关检查或仍有效的原运行证据建立基线，然后实现过滤逻辑；对现有测试未保护的确定性规则补充行为测试，不增加无关功能。按 issue 命令验证，再完成实际受影响的回归、类型或构建检查；界面行为有变化时验证对应页面。

需要留下的材料是：作为权威需求的 issue 链接或稳定 ID、功能分支与聚焦差异、必要测试，以及绑定实际版本和环境的检查结果与限制。可把简短实施和验证说明写回现有本地任务记录，并准备供独立 PR 审查使用的本地材料。无需因为缺少某个模板文件而创建整套治理目录。

本轮授权只到本地实现。项目要求的独立 PR 审查在合并/发布前完成；远端建 PR、合并或部署按后续相应授权进行。审查尚未完成不妨碍先完成安全、可逆的本地实施与验证。

本场景无工具，尚未检查分支、修改文件或运行命令；这里是实施起点和最小交付要求，不能报告为已完成代码或已通过验证。
