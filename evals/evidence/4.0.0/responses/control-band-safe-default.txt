安全初始状态应是全局 disabled、active_tier 为 disabled、所有 tier 的 enabled 都为 false；生产直接变更、自动部署和自动回滚均为 false。先设计和验证检测器，再逐级授权，不因一次阈值越界自动给 agent 更多权限。

启用前先明确指标定义、数据来源、采样窗口、足够的历史基线和样本量、负责人及低噪声升级渠道。用确定性代码检测异常，并测试正常、越界、数据缺失或过期、重复事件及恢复场景；阈值、持续窗口、冷却和去重策略依据真实业务基线确定，模板的 sigma 阈值不能直接当作通用生产标准。

四个层级按以下权限推进：

| 层级 | 允许行为 | 主要边界 |
|---|---|---|
| Observe | 记录越界与脱敏证据 | 不调用有行动能力的 agent，不变更业务系统 |
| Diagnose | 调用只读 agent 分析已触发的证据 | 无代码、基础设施、业务数据或外部系统写权限；不能发消息、部署或回滚 |
| Propose | 生成 intent、issue 或 PR 供正常评审 | 创建外部记录需相应写入授权；不合并、不发布，沿用既有审查和质量门禁 |
| Runbook | 执行明确命名、预先批准且演练过的 runbook | 限定身份和参数、幂等、有限重试、完整审计及已测试 kill switch |

检测必须在模型之外完成；模型只在确定性检测器触发后解释证据，输出按结构验证，工具调用再经模型外的确定性授权。外部内容按不可信输入处理。设置调用次数、超时、输出大小和成本上限，防止告警风暴、重试循环或提示注入扩大权限。

配置沿用 AUTONOMY_BANDS 模板的 JSON-compatible YAML，解析时拒绝重复键并检查布尔类型。启用时只允许一个 active_tier，且仅该 tier 为 true；不支持“全局启用但没有合法活动层级”。每次转换记录前一层级、批准者、批准证据、验证证据及激活时间。

生产 mutation、部署或自动回滚即使采用 runbook 也继续默认关闭；启用属于 R3，另需明确人类批准、恢复证据、必要的独立专业审查及确定性授权。统计阈值本身永远不构成生产操作许可。

持续记录误报、忽略原因、越界到诊断耗时、被接受的发现及重复事故；噪声、模型漂移或运行风险超界时禁用或降级。当前仅交付设计，尚未创建配置、连接监控、调用 agent 或启用任何自动化。
