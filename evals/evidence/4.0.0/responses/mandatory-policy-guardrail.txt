“生产凭据不得暴露给编码 agent”必须由代理无权修改的环境边界强制执行。在 skill、AGENTS.md 或提示词中写这句话只有指导作用；日志脱敏和代理承诺也不能阻止它先读到凭据。该安全基础按 R3 设计和审查。

建议的硬控制是：

- 编码 agent 运行在隔离的开发环境，只挂载必要的源码和合成测试数据；生产密钥不进入其环境变量、文件系统、进程参数、工具返回、日志或提示词。宿主管理面控制挂载、身份和网络策略，agent 不能自行解除隔离，也不能通过宿主 socket 或高权限工具绕过边界。
- 默认拒绝不必要的网络出口；明确阻止云元数据、生产凭据服务及生产管理接口。所需开发访问使用独立、短期、最小权限身份。需要生产诊断时，由可信边界提供脱敏结果，不能把生产凭据返回给 agent。
- 构建与部署身份分开：不可信代码和 PR 检查任务拿不到生产 secret；受保护的发布环境只接受审核过的确切产物，由独立执行器获取短期部署权限。涉及发布工作流或凭据策略的改动也受独立审查保护，防止 agent 改脚本后借 CI 泄漏密钥。
- 密钥扫描、输出过滤和日志脱敏作为补充检测；关键读取在权限层直接拒绝，不能依赖模型识别敏感内容。紧急处理由具名人类在 agent 边界之外完成，不能用 break-glass 把生产 secret 临时注入编码上下文。

把这项强制策略登记到现有 GUARDRAIL_CONTRACT 或等效记录，写明策略 ID、范围、执行点、拒绝方式、责任人、控制版本及验证证据。验证使用无敏感性的哨兵值，覆盖允许的开发操作以及被拒绝的环境变量、挂载、元数据、密钥服务、CI 和输出通路；还要测试 agent 无法更改控制本身。保留独立执行器产生的测试及审计记录，不让模型的自述充当通过证据。

发现真实凭据暴露时，停止使用、吊销或轮换、处理历史和产物并核查访问影响，按事故记录复盘。当前没有目标环境和控制配置，尚未实施或验证隔离；不能据此声称策略已经强制生效，也不能把无证据的提示规则用于支持发布通过。
