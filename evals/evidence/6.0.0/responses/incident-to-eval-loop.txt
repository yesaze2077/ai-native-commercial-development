The incident should produce a durable regression case and a targeted prevention change, with an owner and evidence that the change works. A restored service alone does not close the learning loop.

1. Preserve the incident timeline, affected version/configuration, user impact, detection and recovery evidence. Separate the direct defect from systemic causes: misunderstood requirements, a missed failure path, unsafe tool authority, missing telemetry or an ineffective gate. Keep sensitive data out of the reproduction.
2. Reproduce the failure in an isolated environment and add an application regression test that fails for the original defect and passes with the fix. Improve the smallest relevant test, alert, runbook, contract or deterministic control. Do not turn one incident automatically into a universal instruction.
3. For a material incident involving agent behavior, add a permanent behavior-evaluation case: triggering context, expected action and refusal/escalation boundary, observed failure, and supporting evidence. Include adjacent negative cases so the fix does not merely memorize the incident. Link the incident, corrective action and evaluation IDs.
4. If a skill change is warranted, record a candidate hypothesis, affected task types, baseline, success and safety measures, sample, stopping condition and rollback. Capture fresh real-agent responses, replay the behavior checks, and obtain an independent semantic review bound to their raw-response digests. Compare a compatible baseline; new cases are additional coverage, not a comparable improvement rate. Core governance or approval-policy changes require explicit human approval and the required protected trust mechanism; local passing hashes do not establish approval. Do not auto-merge or activate production autonomy.

Measure incident-to-eval lead time, repeated incidents, escaped defects, change failure and recovery time. Also measure accepted-task success, rework, owner intervention and time/cost per accepted change, so added process does not conceal a productivity regression. Define each clock, population, source, observation window and owner before comparing results. Track alert false positives if detection changes. Review corrective actions until their evidence is complete; claim prevention only over the observed exposure/window, with limitations.
